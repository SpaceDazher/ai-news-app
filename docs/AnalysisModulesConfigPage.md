## Документация: Страница Конфигурации Модулей Анализа (`AnalysisModulesConfigPage`)

**Файл:** `docs/pages/analysis-modules-config.md` (или секция в `docs/pages-documentation.md`)

**1. Назначение Страницы**

Страница Конфигурации Модулей Анализа (`AnalysisModulesConfigPage`) предоставляет интерфейс для **просмотра, настройки и управления** различными модулями, используемыми в конвейере анализа текста. Эта страница предназначена **в первую очередь для администраторов или разработчиков системы** (а не для рядовых пользователей), чтобы:

*   Получить обзор всех доступных модулей анализа.
*   Понимать назначение и текущий статус каждого модуля.
*   **Настраивать параметры** модулей (например, изменять промпты для LLM).
*   **Включать или отключать** определенные модули анализа.
*   (В будущем) Мониторить состояние и производительность модулей.

**2. Пользовательский Поток (User Flow)**

*   Администратор/разработчик переходит на страницу `/admin/modules` (или аналогичный защищенный маршрут).
*   На странице отображается **список всех модулей анализа**, используемых в системе (Классификация, Тональность, NER, Резюмирование, Оценка Важности, Анализ Паттернов).
*   Для каждого модуля в списке отображается:
    *   Название модуля.
    *   Краткое описание его назначения.
    *   Текущий **статус** (Включен / Отключен).
    *   Кнопка или иконка для **перехода к детальной настройке**.
*   Пользователь нажимает на кнопку настройки для конкретного модуля (например, "Классификация по Темам").
*   Открывается **панель деталей/редактирования** (справа или в модальном окне) для выбранного модуля.
*   В панели деталей отображается:
    *   Полное описание модуля.
    *   Текущий статус (с возможностью переключения Вкл/Выкл).
    *   **Текущий промпт**, используемый для LLM (если модуль использует LLM).
    *   (Опционально для MVP) Другие настраиваемые параметры (например, веса для модуля Оценки Важности, выбор LLM модели).
*   Пользователь может **редактировать промпт** в текстовом поле.
*   Пользователь может **переключить статус** модуля (Вкл/Выкл).
*   Пользователь нажимает кнопку **"СОХРАНИТЬ"**, чтобы применить изменения. Система валидирует данные и сохраняет новую конфигурацию через API.
*   Пользователь нажимает кнопку **"ОТМЕНА"**, чтобы закрыть панель деталей без сохранения.
*   Список модулей на основной странице обновляется, отражая новый статус.

**3. Примерный UI (Концепция)**

*   **Основная Область:**
    *   Заголовок "Конфигурация Модулей Анализа".
    *   **Список Модулей:** Таблица или список карточек.
        *   Каждая строка/карточка: Название Модуля, Краткое Описание, Переключатель Статуса (Вкл/Выкл), Кнопка "Настроить" (или иконка шестеренки).
*   **Панель Деталей / Модальное Окно Настройки (появляется при клике "Настроить"):**
    *   Заголовок: "Настройка: [Название Модуля]".
    *   Полное описание назначения модуля.
    *   Переключатель "Статус": Включен / Отключен.
    *   **Редактор Промпта:**
        *   Метка "Промпт для LLM:".
        *   Многострочное текстовое поле (`<textarea>`) для просмотра и редактирования промпта.
        *   (Опционально) Подсказки по доступным переменным в промпте (например, `{text}`, `{categories}`).
    *   **(Опционально) Другие Параметры:** Поля для ввода числовых значений (веса), выпадающие списки (выбор модели).
    *   Кнопки: "СОХРАНИТЬ ИЗМЕНЕНИЯ", "ОТМЕНА".

**4. Архитектура FSD и Компоненты**

*   **Страница (`pages/admin/modules/AnalysisModulesConfigPage.tsx`):**
    *   Рендерит `ManageAnalysisModulesFeature`.
    *   **Важно:** Эта страница должна быть защищена роутингом только для администраторов (`AdminProtectedRoute` или аналогичный механизм).
    *   Загружает список конфигураций модулей при монтировании.

*   **Фича (`features/manageAnalysisModules/ManageAnalysisModulesFeature.tsx`):**
    *   Основной контейнер логики управления модулями.
    *   **Состояние:** `modulesConfig` (массив конфигураций модулей), `selectedModuleId` (для панели редактирования), `isEditing` (флаг открытия панели), `isLoading`, `error`.
    *   **Хуки:** `useAnalysisModulesConfig` (из `entities/analysisModule`) для получения и обновления конфигураций.
    *   **Обработчики:**
        *   `handleToggleStatus(moduleId, newStatus)`: Вызывает API для обновления статуса.
        *   `handleOpenEdit(moduleId)`: Устанавливает `selectedModuleId`, `isEditing = true`.
        *   `handleCloseEdit()`: Сбрасывает `selectedModuleId`, `isEditing = false`.
        *   `handleSaveConfig(moduleId, newConfig)`: Валидирует `newConfig` (особенно промпт), вызывает API для обновления, закрывает панель редактирования.
    *   **Рендеринг:** `ModulesList`, `ModuleConfigPanel` (или модалка).

*   **UI Компоненты Фичи (`features/manageAnalysisModules/ui/`):**
    *   `ModulesList.tsx`: Отображает список/таблицу модулей. Использует `ModuleListItem`.
    *   `ModuleListItem.tsx`: Отображает одну строку/карточку модуля с названием, описанием, переключателем статуса и кнопкой "Настроить".
    *   `ModuleConfigPanel.tsx` (или `Modal`): Панель/модалка для редактирования. Принимает `moduleConfig`, обработчики `onSave`, `onCancel`. Содержит `PromptEditor` и другие поля.
    *   `PromptEditor.tsx`: Компонент для редактирования промпта (может быть просто оберткой над `shared/ui/TextArea`).

*   **Сущность (`entities/analysisModule/`):**
    *   `model/types.ts`: Интерфейс `IAnalysisModuleConfig` (`id` (или `moduleId` как string, например, "classification"), `name`, `description`, `isEnabled`, `prompt` (string, опционально), `parameters` (object, опционально)).
    *   `api/moduleConfigApi.ts`: Функции для взаимодействия с API (`fetchModulesConfig`, `updateModuleConfig(moduleId, config)`).
    *   `model/slice.ts`: Redux slice (`modulesConfigSlice`) для хранения состояния конфигураций модулей.
    *   `hooks/useAnalysisModulesConfig.ts`: Хук для доступа к конфигурациям.

*   **Общие Компоненты (`shared/ui/`):**
    *   `Table.tsx` или `List.tsx`, `Card.tsx`, `ToggleSwitch.tsx`, `Button.tsx`, `Modal.tsx`, `TextArea.tsx`, `Spinner.tsx`, `ErrorMessage.tsx`.

**5. API Дизайн: REST API для Конфигурации Модулей**

**Важно:** Эти эндпоинты должны быть **строго защищены** и доступны только пользователям с ролью администратора.

*   **`GET /api/admin/analysis-modules`**
    *   **Назначение:** Получить список всех модулей анализа и их текущие конфигурации.
    *   **Request Headers:** `Authorization: Bearer <JWT>` (с проверкой роли администратора на backend).
    *   **Логика Backend:** Получить конфигурации всех модулей (могут храниться в отдельной коллекции MongoDB `ModuleConfigs` или даже в конфигурационных файлах, если они не меняются пользователем часто; для изменяемых промптов - лучше в БД).
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        [
          { "moduleId": "classification", "name": "Классификация", "description": "...", "isEnabled": true, "prompt": "...", "parameters": {} },
          { "moduleId": "sentiment", "name": "Анализ Тональности", "description": "...", "isEnabled": true, "prompt": "...", "parameters": {} },
          // ... другие модули
        ]
        ```
    *   **Response Body (JSON - Ошибка, 401/403):** `{"error": "Unauthorized or Forbidden"}`

*   **`PUT /api/admin/analysis-modules/:moduleId`**
    *   **Назначение:** Обновить конфигурацию конкретного модуля.
    *   **Request Headers:** `Authorization: Bearer <JWT>` (с проверкой роли администратора).
    *   **URL Parameters:** `:moduleId` (например, `classification`, `sentiment`).
    *   **Request Body (JSON):** Объект с обновляемыми полями.
        ```json
        {
          "isEnabled": false, // Пример: отключение модуля
          "prompt": "Новый текст промпта..." // Пример: обновление промпта
          // "parameters": { "weight": 0.7 } // Пример: обновление параметров
        }
        ```
    *   **Логика Backend:**
        1.  Проверить JWT и роль администратора.
        2.  Найти конфигурацию модуля по `:moduleId`.
        3.  Валидировать входные данные (например, проверить синтаксис промпта, если возможно).
        4.  Обновить конфигурацию модуля в MongoDB (или где она хранится).
        5.  **Важно:** Backend-воркеры, выполняющие анализ, должны будут при следующем запуске **считывать актуальную конфигурацию** (включен ли модуль, какой промпт использовать).
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        { "moduleId": "...", "name": "...", ... } // Возвращаем обновленную конфигурацию
        ```
    *   **Response Body (JSON - Ошибка, 400/401/403/404):** `{"error": "..."}`

**6. Взаимодействие с Другими Компонентами/Модулями**

*   Изменения, сохраненные на этой странице через API, **напрямую влияют на работу backend-воркеров**, которые выполняют анализ текста. Воркеры должны перед каждым анализом (или при инициализации) считывать актуальную конфигурацию модуля из базы данных (или кэша), чтобы использовать правильный промпт и знать, включен ли модуль.
*   Эта страница не взаимодействует напрямую с другими UI-страницами, кроме как через изменение глобальной конфигурации анализа.

**7. Безопасность**

*   **Ролевая Модель:** Доступ к этой странице и ее API должен быть строго ограничен ролью "Администратор". Реализовать проверку роли на backend в middleware.
*   **Валидация Промптов:** На backend следует предусмотреть хотя бы базовую валидацию или санацию сохраняемых промптов, чтобы избежать потенциальных проблем с инъекциями или некорректной работой LLM (хотя это сложно).
*   **Аудит (Опционально):** Логгировать изменения конфигурации модулей (кто, когда и что изменил).

**8. Fit в MVP**

*   **Минимальная Реализация:**
    *   Отображение списка модулей с их названиями и описаниями (можно захардкодить на старте, если они не динамические).
    *   Возможность **включать/отключать** модули (переключатель + сохранение статуса через API). Backend должен учитывать этот статус при обработке.
    *   Возможность **просмотра и редактирования промптов** для модулей, использующих LLM (текстовое поле + сохранение через API). Backend должен использовать сохраненный промпт.
*   **Отложить на Будущее:**
    *   Редактирование других параметров (веса, модели LLM).
    *   Мониторинг статуса работы/ошибок модулей.
    *   Тестирование модулей.
    *   Логгирование.
