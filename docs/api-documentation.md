# Документация Backend API

## Обзор

Этот документ описывает REST API эндпоинты, предоставляемые Backend приложением (Next.js API Routes).  API используется Frontend приложением (React SPA) для взаимодействия с Backend логикой, обработки данных и получения результатов анализа.

## Аутентификация

Для защищенных эндпоинтов требуется аутентификация пользователя.  Аутентификация осуществляется с использованием **JSON Web Tokens (JWT)**.

*   После успешной аутентификации (например, через эндпоинт `/api/auth/login`), Backend возвращает JWT в ответе.
*   Для доступа к защищенным эндпоинтам, Frontend должен включать JWT в заголовок `Authorization` каждого запроса в формате:

    ```
    Authorization: Bearer <JWT>
    ```

    Где `<JWT>` - полученный JSON Web Token.

## Эндпоинты API

### 1. `/api/processText`

*   **HTTP Метод:** `POST`
*   **Назначение:**  Отправить сырой текст для анализа.  Backend приложение выполнит предобработку текста и запустит конвейер анализа (классификация, тональность, сущности, резюме, оценка важности).  Результаты анализа будут сохранены в базе данных и отправлены Frontend через WebSocket (в реальном времени).
*   **Аутентификация:** **Требуется** (защищенный эндпоинт).  Только авторизованные пользователи могут запускать анализ текста.
*   **Формат Запроса:**
    *   **Headers:**
        *   `Content-Type: application/json`
        *   `Authorization: Bearer <JWT>` (для авторизованных запросов)
    *   **Body (JSON):**

        ```json
        {
          "rawText": "Сырой текст для анализа..."
        }
        ```

        *   `rawText` (String, **обязательное**):  Сырой текст, который необходимо проанализировать.

*   **Формат Ответа:**
    *   **Успешный ответ (HTTP 202 Accepted):**

        ```json
        {
          "message": "Текст принят на обработку. Результаты анализа будут отправлены через WebSocket.",
          "taskId": "<task-id>" // Опционально: ID задачи обработки (для отслеживания прогресса в будущем)
        }
        ```

        *   **HTTP Код:** `202 Accepted` (Текст успешно принят в очередь на обработку. Фактический анализ может занять некоторое время и результаты будут отправлены асинхронно через WebSocket).
        *   `message` (String): Сообщение об успехе.
        *   `taskId` (String, опционально):  Идентификатор задачи обработки (может быть использован в будущем для отслеживания статуса и прогресса обработки, пока на MVP можно опустить).

    *   **Ошибка (HTTP 400 Bad Request):**

        ```json
        {
          "error": "Некорректный запрос.",
          "details": "<описание ошибки>"
        }
        ```

        *   **HTTP Код:** `400 Bad Request`
        *   `error` (String): Общее описание ошибки.
        *   `details` (String):  Детальное описание ошибки (например, "поле 'rawText' не может быть пустым").

    *   **Ошибка Авторизации (HTTP 401 Unauthorized):**

        ```json
        {
          "error": "Не авторизован.",
          "message": "Требуется аутентификация для доступа к этому эндпоинту."
        }
        ```

        *   **HTTP Код:** `401 Unauthorized`
        *   `error` (String):  Общее описание ошибки авторизации.
        *   `message` (String):  Пояснение, что требуется аутентификация.


### 2. `/api/auth/login`

*   **HTTP Метод:** `POST`
*   **Назначение:**  Аутентификация пользователя и получение JWT (JSON Web Token).
*   **Аутентификация:** **Не требуется** (открытый эндпоинт для входа в систему).
*   **Формат Запроса:**
    *   **Headers:**
        *   `Content-Type: application/json`
    *   **Body (JSON):**

        ```json
        {
          "login": "<логин-пользователя>",
          "password": "<пароль-пользователя>"
        }
        ```

        *   `login` (String, **обязательное**):  Логин пользователя.
        *   `password` (String, **обязательное**):  Пароль пользователя.

*   **Формат Ответа:**
    *   **Успешный ответ (HTTP 200 OK):**

        ```json
        {
          "token": "<JWT-токен>",
          "message": "Аутентификация успешна."
        }
        ```

        *   **HTTP Код:** `200 OK`
        *   `token` (String): **JSON Web Token (JWT)**, который Frontend должен использовать для авторизации в защищенных эндпоинтах.
        *   `message` (String): Сообщение об успехе аутентификации.

    *   **Ошибка Аутентификации (HTTP 401 Unauthorized):**

        ```json
        {
          "error": "Неверные учетные данные.",
          "message": "Неверный логин или пароль."
        }
        ```

        *   **HTTP Код:** `401 Unauthorized`
        *   `error` (String):  Общее описание ошибки аутентификации.
        *   `message` (String):  Пояснение, что неверные учетные данные.

    *   **Ошибка (HTTP 400 Bad Request):**

        ```json
        {
          "error": "Некорректный запрос.",
          "details": "<описание ошибки>"
        }
        ```

        *   **HTTP Код:** `400 Bad Request`
        *   `error` (String): Общее описание ошибки.
        *   `details` (String):  Детальное описание ошибки (например, "поле 'login' не может быть пустым").


### 3. `/api/socket`

*   **HTTP Метод:** `GET` (для установления WebSocket соединения).
*   **Назначение:**  Установить WebSocket соединение для получения обновлений анализа в реальном времени.  **Это не REST API эндпоинт в традиционном смысле, а точка подключения WebSocket сервера.**
*   **Аутентификация:**  **В MVP - не требуется** (открытое WebSocket соединение для простоты MVP).  В будущем, возможно, потребуется авторизация WebSocket соединений.
*   **Формат Запроса:**
    *   **HTTP GET Request:**  Frontend приложение инициирует WebSocket соединение, отправляя GET запрос на `/api/socket`.  Обычно это делается автоматически WebSocket клиентом на frontend.
*   **Формат Сообщений WebSocket:**
    *   **Backend -> Frontend (сообщение `analysis-update`):**

        ```json
        {
          "type": "analysis-update",
          "data": {
            "analysisId": "<ID-анализа>",
            "category": "<категория-новости>",
            "sentiment": "<тональность-новости>",
            "entities": [ { "entity": "...", "type": "..." }, ... ],
            "summary": "<краткое-резюме>",
            "importanceScore": <оценка-важности>
            // ... другие результаты анализа ...
          }
        }
        ```

        *   `type` (String):  Тип сообщения - `"analysis-update"` для обновлений результатов анализа.
        *   `data` (Object):  Объект, содержащий результаты анализа:
            *   `analysisId` (String): Идентификатор анализа.
            *   `category` (String):  Категория новости.
            *   `sentiment` (String):  Тональность новости.
            *   `entities` (Array of Objects):  Список извлеченных сущностей.
            *   `summary` (String):  Краткое резюме новости.
            *   `importanceScore` (Number):  Оценка важности новости.
            *   **В будущем можно расширить `data` другими полями, добавленными в модули анализа.**
