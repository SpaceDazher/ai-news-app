## Документация: Frontend Приложения

**Файл:** `docs/frontend.md`

**1. Обзор Архитектуры Frontend**

Frontend приложения представляет собой **Одностраничное Приложение (Single Page Application - SPA)**, разработанное с использованием **React** и **TypeScript**. Архитектура построена на принципах **Feature-Sliced Design (FSD)**, что обеспечивает высокую модульность, масштабируемость и поддерживаемость кода.

Frontend отвечает за:

*   Отображение пользовательского интерфейса (UI).
*   Обработку пользовательского ввода и взаимодействий.
*   Управление состоянием приложения (данные пользователя, источники, результаты анализа, дашборды и т.д.).
*   Взаимодействие с Backend API для получения и отправки данных.
*   Отображение данных в реальном времени с использованием WebSocket.
*   Маршрутизацию между различными страницами приложения.

**2. Технологический Стек Frontend**

*   **Библиотека UI:** React (v18+)
*   **Язык:** TypeScript
*   **Управление состоянием:** Redux Toolkit
*   **Маршрутизация:** React Router (v6+)
*   **Взаимодействие с API:** Axios или Fetch API (рекомендуется создать обертку в `shared/api`)
*   **Real-time:** Socket.IO Client
*   **Визуализация данных:** Chart.js (с `react-chartjs-2`) или Recharts
*   **Сборка:** Vite или Create React App (согласно предыдущему плану)
*   **UI Компоненты (Опционально):** Может использоваться UI-библиотека (например, Material-UI, Ant Design, Chakra UI) для ускорения разработки или кастомные компоненты, стилизованные с помощью CSS Modules, Styled Components или Tailwind CSS.

**4. Основные Обязанности Frontend**

*   **Отображение UI:** Рендеринг страниц и компонентов на основе текущего состояния.
*   **Управление Состоянием:** Использование Redux Toolkit для централизованного хранения и управления состоянием приложения (данные пользователя, токены, списки источников/папок/постов, данные дашбордов, статусы загрузки, ошибки).
*   **Маршрутизация:** Использование React Router для навигации между страницами (`AuthPage`, `ManageSourcesPage`, `DataViewerPage`, `MainDashboardPage` и др.) и защиты маршрутов, требующих аутентификации.
*   **Взаимодействие с API:** Отправка запросов к Backend API (Next.js) для аутентификации, получения и отправки данных (источники, посты, анализ, конфигурации). Обработка ответов и ошибок API.
*   **Обработка Пользовательского Ввода:** Валидация форм (вход, регистрация, добавление источников/папок), обработка кликов, изменений в полях ввода.
*   **Отображение Real-time Обновлений:** Установка WebSocket соединения (после аутентификации), прослушивание событий от сервера (например, `analysis-update`) и обновление соответствующей части состояния Redux для динамического отображения прогресса или результатов анализа.
*   **Визуализация Данных:** Отображение графиков и диаграмм на дашбордах с использованием Chart.js/Recharts.

**5. Управление Состоянием (Redux Toolkit)**

*   **Store:** Единый источник истины для всего состояния приложения, конфигурируемый в `app/providers/StoreProvider.tsx`.
*   **Slices:** Состояние разделено на логические части (slices), каждая из которых управляет определенной частью данных (например, `authSlice`, `sourcesSlice`, `postsSlice`, `foldersSlice`, `dashboardSlice`, `modulesConfigSlice`). Каждый slice создается с помощью `createSlice` и включает в себя:
    *   Начальное состояние (`initialState`).
    *   Редьюсеры (`reducers`) для обработки синхронных действий.
    *   Асинхронные действия (`createAsyncThunk`) для взаимодействия с API (загрузка данных, отправка форм), которые автоматически управляют статусами `pending`, `fulfilled`, `rejected`.
*   **Selectors:** Функции (`createSelector` из `reselect` для оптимизации), используемые компонентами для извлечения необходимых данных из store (`useSelector` hook).
*   **Dispatch:** Компоненты используют хук `useDispatch` для отправки действий (синхронных или асинхронных thunks) в store для изменения состояния.

**6. Маршрутизация (React Router)**

*   **Конфигурация:** Определяется в `app/routes/index.tsx` с использованием `<BrowserRouter>`, `<Routes>`, `<Route>`.
*   **Основные Маршруты (Примеры):**
    *   `/auth`: `AuthPage`
    *   `/manage-sources`: `ManageSourcesPage` (защищенный)
    *   `/data-viewer`: `DataViewerPage` (защищенный)
    *   `/dashboard`: `MainDashboardPage` (главная защищенная страница)
    *   `/folders`: `ClassificationDashboardPage` (защищенный)
    *   `/folders/:folderId`: `FolderContentPage` (защищенный)
    *   `/admin/modules`: `AnalysisModulesConfigPage` (защищенный, требует роли админа)
*   **Защита Маршрутов (`ProtectedRoute`):** Создается компонент-обертка `ProtectedRoute`, который проверяет статус аутентификации пользователя (из `authSlice` или `useAuth`). Если пользователь не аутентифицирован, он перенаправляет на `/auth`. Если требуется определенная роль (например, админ), проверка выполняется аналогично.

**7. Взаимодействие с API**

*   **API Client:** Рекомендуется создать централизованный API клиент (например, настроенный экземпляр Axios или обертки над Fetch) в `shared/api`. Этот клиент будет автоматически добавлять базовый URL API и JWT токен (если он есть) ко всем исходящим запросам.
*   **API Функции:** Для каждой сущности (`entities/*`) создаются функции API (`entities/*/api/*.ts`), которые используют API клиент для выполнения конкретных запросов (например, `fetchSources`, `loginUser`, `fetchDashboardData`).
*   **Интеграция с Redux:** Асинхронные действия (`createAsyncThunk`) в Redux slices вызывают эти API функции, обрабатывают промисы и обновляют состояние (данные, статус загрузки, ошибки).

**8. Real-time Обновления (WebSocket)**

*   **Подключение:** Используется библиотека `socket.io-client`. Соединение устанавливается **после успешной аутентификации** пользователя (например, в главном компоненте приложения `App.tsx` или в специальном хуке `useWebSocket`).
*   **Прослушивание Событий:** Клиент подписывается на серверные события, определенные в API (например, `socket.on('analysis-update', (data) => { ... });`).
*   **Обновление Состояния:** При получении события от сервера, клиент диспатчит соответствующее действие Redux (например, `dispatch(analysisResultSlice.actions.updateAnalysis(data))`), чтобы обновить состояние и, следовательно, UI.
*   **Отключение:** Соединение закрывается при выходе пользователя (`socket.disconnect()`).

**9. Аутентификация (Клиентская Сторона)**

*   **Хранение Токена:** JWT, полученный от API при логине, сохраняется (например, в `localStorage`) для персистентности между сессиями. `authSlice` считывает токен из `localStorage` при инициализации приложения и хранит его в состоянии для легкого доступа.
*   **Прикрепление Токена:** API клиент автоматически прикрепляет токен из `authSlice` к заголовку `Authorization` защищенных запросов.
*   **Logout:** Функция `logout` в `authSlice` очищает токен из состояния и `localStorage`, сбрасывает данные пользователя и инициирует перенаправление на `/auth`.
*   **Обработка 401:** API клиент может перехватывать ответы с кодом 401 Unauthorized и автоматически выполнять выход пользователя (вызывать `logout`).

**10. UI Компоненты и Стилизация**

*   **Переиспользуемость:** Следование FSD способствует созданию переиспользуемых компонентов на уровнях `shared/ui` и `widgets`.
*   **Стилизация:** Выбрать единый подход (CSS Modules, Styled Components, Tailwind CSS или UI библиотеку) и придерживаться его во всем проекте для консистентности. Стили компонента должны быть инкапсулированы в его модуле FSD.

**11. Обработка Ошибок**

*   **Ошибки API:** Состояние ошибок, полученных от API, хранится в соответствующих Redux slices (`slice.error`). Компоненты могут отображать эти ошибки пользователю (например, через `ErrorMessage` из `shared/ui` или toast-уведомления).
*   **Ошибки Валидации Форм:** Реализуются локально в `features` (например, в `AuthFeature`) с использованием состояния компонента или библиотек управления формами. Сообщения об ошибках отображаются рядом с полями ввода.
*   **Ошибки WebSocket:** Обрабатывать ошибки подключения или получения сообщений от WebSocket сервера и информировать пользователя при необходимости.

**12. Сборка и Деплой**

*   **Сборка:** Команда `npm run build` создает оптимизированную статическую сборку SPA в папке `build` или `dist`.
*   **Деплой:** Статические файлы могут быть развернуты на любой платформе для хостинга статики:
    *   **Vercel / Netlify:** Отличный выбор, простая интеграция с Git, CI/CD из коробки.
    *   **AWS S3 + CloudFront:** Классический надежный вариант.
    *   **GitHub Pages:** Бесплатный вариант для простых проектов.
    *   **Docker:** Контейнеризация сборки для деплоя на любую платформу, поддерживающую Docker.
*   **Конфигурация Окружения:** Необходимо настроить переменную окружения (`REACT_APP_API_URL` или `VITE_API_URL`), указывающую на URL развернутого Backend API.
