## Документация: Страница Просмотра Данных (`DataViewerPage`)

**Файл:** `docs/pages/data-viewer.md` (или секция в `docs/pages-documentation.md`)

**1. Назначение Страницы**

Страница Просмотра Данных (`DataViewerPage`, можно назвать "Инспектор" или "Сырые данные") предназначена для **просмотра сырого текстового контента**, который был собран из добавленных пользователем источников данных. Основная цель — предоставить пользователю (в первую очередь, на этапе разработки и отладки, но может быть полезна и конечному пользователю) возможность **убедиться в корректности сбора данных** и увидеть исходный материал **перед** его автоматической обработкой и анализом. Эта страница **не отображает результаты анализа**, только исходные посты.

**2. Пользовательский Поток (User Flow)**

*   Пользователь переходит на страницу `/data-viewer` (например, через боковое меню).
*   Страница разделена на две основные панели:
    *   **Левая панель:** Отображает список всех источников данных, добавленных пользователем. Присутствует поле для поиска по источникам.
    *   **Правая панель:** Отображает список постов/сообщений из **выбранного** в левой панели источника.
*   Пользователь **выбирает источник** в левой панели, кликнув на него. Выбранный источник подсвечивается.
*   При выборе источника **правая панель динамически обновляется**, загружая и отображая список последних постов из этого источника, отсортированных по дате (сверху самые новые).
*   Каждый пост в правой панели отображается в виде краткой карточки (например, "ПОСТ - ДАТА - ТИП") и имеет кнопку **"РАСКРЫТЬ ТЕКСТ"**.
*   Пользователь нажимает кнопку "РАСКРЫТЬ ТЕКСТ" для интересующего поста.
*   Под карточкой поста **динамически разворачивается область, отображающая полный сырой текст** данного поста.
*   Кнопка "РАСКРЫТЬ ТЕКСТ" меняется на **"СВЕРНУТЬ ТЕКСТ"**. При повторном нажатии область с текстом сворачивается.
*   Пользователь может выбрать другой источник в левой панели, и правая панель обновится соответствующим образом.

**3. Примерный UI (Концепция на основе Wireframe)**

*   **Двухпанельный Макет:**
    *   **Левая Панель:**
        *   Поле "ПОИСК" (для источников).
        *   Вертикальный список кликабельных блоков "ИСТОЧНИК".
        *   Выделение (фон, рамка) для активного/выбранного источника.
        *   (Опционально) Иконка типа источника рядом с названием.
    *   **Правая Панель:**
        *   Заголовок (может показывать название выбранного источника).
        *   Вертикальный список карточек постов:
            *   Каждая карточка содержит: "ПОСТ" (заголовок/превью), "ДАТА", "ТИП" (лучше **"ИСТОЧНИК"** или убрать, т.к. источник выбран слева).

**4. Архитектура FSD и Компоненты**

*   **Страница (`pages/data-viewer/DataViewerPage.tsx`):**
    *   Отвечает за рендеринг `DataViewerFeature`.
    *   При монтировании инициирует загрузку списка источников пользователя.

*   **Фича (`features/dataViewer/DataViewerFeature.tsx`):**
    *   Основной контейнер логики просмотра данных.
    *   **Состояние:** `sources` (список источников), `selectedSourceId` (ID выбранного источника), `posts` (список постов для выбранного источника), `expandedPostId` (ID поста, текст которого раскрыт), `isLoadingSources`, `isLoadingPosts`, `error`.
    *   **Хуки:**
        *   `useSources` (из `entities/source`): Для получения списка источников.
        *   `usePosts` (из `entities/post`): Для получения постов для `selectedSourceId`.
    *   **Обработчики:**
        *   `handleSourceSelect(sourceId)`: Обновляет `selectedSourceId`, инициирует загрузку постов для нового источника.
        *   `handleToggleText(postId)`: Обновляет `expandedPostId` (либо устанавливает ID, либо null для сворачивания).
        *   `handleSearchChange()`: Фильтрует список `sources` (клиентская фильтрация или запрос к API, если источников очень много).
    *   **Рендеринг:** Компоненты `SourceSelectorPanel` и `PostViewerPanel`.

*   **UI Компоненты Фичи (`features/dataViewer/ui/`):**
    *   `SourceSelectorPanel.tsx`: Рендерит левую панель со списком источников и поиском. Принимает `sources`, `selectedSourceId`, `onSelectSource`, `onSearchChange` через props.
    *   `SourceListItem.tsx`: Компонент для отображения одного источника в левой панели. Принимает `source`, `isSelected`, `onClick` через props.
    *   `PostViewerPanel.tsx`: Рендерит правую панель со списком постов. Принимает `posts`, `expandedPostId`, `onToggleText` через props.
    *   `PostCard.tsx`: Компонент для отображения одной карточки поста в правой панели. Принимает `post`, `isExpanded`, `onToggleText` через props. Рендерит кнопку "Раскрыть/Свернуть" и опционально `RawTextViewer`.
    *   `RawTextViewer.tsx`: Компонент для отображения сырого текста поста. Принимает `rawText` через props. Может включать минимальное форматирование или переключатель "сырой/форматированный".

*   **Сущности:**
    *   `SourceEntity` (`entities/source/`): Используется для получения списка источников (`useSources`).
    *   `PostEntity` (`entities/post/`):
        *   `model/types.ts`: Интерфейс `IPost` (`id`, `sourceId`, `title`, `rawText`, `publicationDate`, `url` и т.д.).
        *   `api/postApi.ts`: Функции `fetchPostsBySource(sourceId, page, limit)`, `fetchPostRawText(postId)`.
        *   `model/slice.ts` (или `context.ts`): Redux slice (`postsSlice`) или Context для кэширования постов по источникам.
        *   `hooks/usePosts.ts`: Хук для загрузки и получения постов для выбранного источника.

*   **Общие Компоненты (`shared/ui/`):**
    *   `Input.tsx` (для поиска), `Button.tsx`, `Spinner.tsx`, `ErrorMessage.tsx`, `Panel.tsx` (для панелей), `List.tsx`.

**5. API Дизайн: REST API для Просмотра Данных**

**Почему REST?** Получение списков (источников, постов) и конкретных данных (текст поста) - это классические задачи для REST API.

*   **`GET /api/sources`**
    *   **(Уже определен для страницы "Управление Источниками")** Используется для получения списка источников в левой панели.

*   **`GET /api/posts`**
    *   **Назначение:** Получить список постов для **конкретного источника**, принадлежащего текущему пользователю.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **Query Parameters:**
        *   `sourceId` (обязательный): ID источника, для которого нужны посты.
        *   `page` (опционально): Номер страницы для пагинации (например, `1`).
        *   `limit` (опционально): Количество постов на странице (например, `20`).
        *   `sortBy` (опционально): Поле для сортировки (например, `publicationDate`).
        *   `sortOrder` (опционально): Порядок сортировки (`asc` или `desc`, по умолчанию `desc` для даты).
    *   **Логика Backend:**
        1.  Проверить JWT, извлечь `userId`.
        2.  Найти источник по `sourceId`. **Проверить, что `source.userId` совпадает с `userId` из токена.**
        3.  Найти в MongoDB (коллекция, где хранятся сырые посты, например `RawPosts` или может быть частью `AnalysisResults`, но лучше отдельная для сырых данных на старте) посты с `sourceId`, применить пагинацию и сортировку. **Возвращать только необходимые поля для превью** (id, title, publicationDate), **не полный `rawText`**.
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        {
          "posts": [
            { "id": "post1", "title": "Заголовок поста 1", "publicationDate": "..." },
            { "id": "post2", "title": "Заголовок поста 2", "publicationDate": "..." }
          ],
          "totalPages": 10, // Для пагинации
          "currentPage": 1   // Для пагинации
        }
        ```
    *   **Response Body (JSON - Ошибка, 400/401/403/404):** `{"error": "..."}`

*   **`GET /api/posts/:postId/raw`**
    *   **Назначение:** Получить **полный сырой текст** конкретного поста.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **URL Parameters:** `:postId` - ID поста, текст которого нужен.
    *   **Логика Backend:**
        1.  Проверить JWT, извлечь `userId`.
        2.  Найти пост по `:postId`.
        3.  **Найти связанный источник и проверить, что `source.userId` совпадает с `userId` из токена.** (Важно для безопасности, чтобы пользователь не мог получить текст чужих постов, зная ID).
        4.  Вернуть поле `rawText` из найденного документа поста.
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        {
          "rawText": "Полный сырой текст поста..."
        }
        ```
    *   **Response Body (JSON - Ошибка, 401/403/404):** `{"error": "..."}`

**6. Взаимодействие с Другими Компонентами/Модулями**

*   `DataViewerFeature` использует `useSources` из `entities/source` для получения списка источников (тех же, что и на странице "Управление Источниками").
*   `DataViewerFeature` использует `usePosts` из `entities/post` для получения и отображения постов.
*   Эта страница работает независимо от модулей анализа, так как ее цель - показать сырые данные *до* анализа.

**7. Безопасность**

*   **Авторизация:** Все API эндпоинты требуют валидный JWT.
*   **Авторизация (Проверка прав):** Backend API должен строго проверять, что пользователь имеет доступ к запрашиваемым источникам и постам (сравнение `userId` из токена с `userId`, связанным с источником/постом).

**8. Fit в MVP**

Эта страница является важной частью MVP, особенно для отладки процесса сбора данных. Реализация с двумя панелями и раскрытием текста вполне достижима в рамках MVP. Использование REST API для получения данных соответствует выбранной архитектуре.
