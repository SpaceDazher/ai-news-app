# Архитектура Приложения для Анализа Новостей

## Обзор

Это приложение разработано как Single Page Application (SPA) с использованием архитектурного подхода Feature-Sliced Design (FSD).  Приложение предназначено для агрегации и анализа новостного контента из различных источников с использованием технологий искусственного интеллекта (LLM).  Основная цель архитектуры – обеспечить масштабируемость, поддерживаемость и гибкость приложения по мере добавления новых функций и усложнения логики.

## Feature-Sliced Design (FSD) Архитектура

FSD – это методология организации кода, которая разделяет приложение на слои и модули, ориентированные на бизнес-логику и функциональные возможности (features), а не на технические аспекты.  Основные слои FSD в нашем приложении:

### Слои FSD

1.  **`Shared` (Общие)**
    *   Содержит код, который используется в разных частях приложения и не привязан к конкретной бизнес-логике.
    *   Примеры: UI-компоненты (кнопки, инпуты, модальные окна), утилитарные функции, хуки, константы.
    *   `src/shared/`

2.  **`Entities` (Сущности)**
    *   Описывает доменные объекты приложения – ключевые понятия и данные, с которыми работает приложение.
    *   Примеры: `User`, `TextAnalysis`, `Dashboard`, `Source`, `Post`.
    *   `src/entities/`

3.  **`Features` (Функциональные Модули)**
    *   Реализует конкретные пользовательские функции и сценарии.  Каждая фича инкапсулирует логику, UI-компоненты и взаимодействие с бэкендом, необходимые для реализации определенной функции.
    *   Примеры: `TextInputFeature` (ввод текста и запуск анализа), `AnalysisResultsFeature` (отображение результатов анализа), `AuthFeature` (авторизация), `DashboardFeature` (дашборды), `SourcesManagementFeature` (управление источниками), `RawTextViewFeature` (просмотр сырого текста).
    *   `src/features/`

4.  **`Pages` (Страницы)**
    *   Представляют собой отдельные страницы приложения, которые объединяют несколько фич и сущностей для формирования целостного пользовательского интерфейса.
    *   Примеры: `TextInputPage`, `AnalysisPage`, `DashboardPage`, `TextPage`, `AuthPage`.
    *   `src/pages/`

5.  **`Widgets` (UI-Компоненты)**
    *   Многократно используемые, более мелкие UI-компоненты, которые могут быть использованы внутри фич и страниц для построения интерфейса.
    *   Примеры: `ChartWidget` (для графиков), `TextCardWidget`, `TableWidget`.
    *   `src/widgets/`

6.  **`App` (Корневой уровень)**
    *   Содержит код, связывающий все слои вместе и настраивающий приложение в целом.
    *   Примеры: Роутинг приложения (React Router), провайдеры для Redux и авторизации, корневой компонент приложения.
    *   `src/app/`

### Взаимодействие Frontend и Backend

Frontend (SPA на React) взаимодействует с Backend (Next.js API Routes) через REST API запросы и WebSocket соединения:

*   **REST API (`/api/*`)**:  Используется для выполнения основных операций:
    *   Отправка текста на анализ (`/api/processText`).
    *   Авторизация пользователя (`/api/auth/login`).
    *   Получение данных для UI (список источников, результаты анализа, данные для дашбордов и т.д.).
*   **WebSocket (`/api/socket`)**:  Используется для передачи обновлений аналитических данных в реальном времени от Backend к Frontend.  Когда Backend завершает анализ текста, он отправляет результаты через WebSocket, и Frontend обновляет UI без перезагрузки страницы.

### База Данных (MongoDB)

MongoDB используется для хранения данных приложения:

*   **Коллекции:**
    *   `Users`:  Информация о пользователях.
    *   `AnalysisResults`:  Сырой текст и результаты анализа для каждого текста.
    *   `Sources`:  Информация об источниках данных (сайты, Telegram-каналы и т.д.).
    *   Возможно добавление других коллекций в будущем.
