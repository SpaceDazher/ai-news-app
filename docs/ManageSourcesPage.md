## Документация: Страница Управления Источниками (`ManageSourcesPage`)

**Файл:** `docs/pages/manage-sources.md` (или секция в `docs/pages-documentation.md`)

**1. Назначение Страницы**

Страница Управления Источниками (`ManageSourcesPage`) предназначена **исключительно для добавления, просмотра, редактирования и удаления списка источников данных**, принадлежащих авторизованному пользователю. Она **не отображает** сами новости или результаты анализа. Это центральное место для конфигурации того, откуда приложение будет собирать контент.

**2. Пользовательский Поток (User Flow)**

*   Пользователь переходит на страницу `/manage-sources` (например, через боковое меню).
*   На странице отображается **список ранее добавленных источников** данных пользователя. Если источников нет, список пуст.
*   Присутствует кнопка **"ДОБАВИТЬ ИСТОЧНИК"**.
*   **Для Добавления Источника:**
    1.  Пользователь нажимает кнопку "ДОБАВИТЬ ИСТОЧНИК".
    2.  Под кнопкой (или в модальном окне) появляется секция выбора **типа источника** (кнопки: "ТЕЛЕГРАММ", "САЙТЫ", "API").
    3.  Пользователь выбирает тип источника (например, кликает "САЙТЫ").
    4.  Динамически отображается **форма для ввода данных**, специфичная для выбранного типа (например, поле "URL Сайта" и опциональное поле "Название").
    5.  Пользователь заполняет форму.
    6.  Пользователь нажимает кнопку **"СОХРАНИТЬ"** (или "ДОБАВИТЬ").
    7.  Система валидирует данные и отправляет запрос на API для создания источника.
    8.  В случае успеха: форма добавления скрывается, и **новый источник появляется в общем списке** на странице. Отображается уведомление об успехе.
    9.  В случае ошибки: отображается сообщение об ошибке рядом с формой.
    10. Пользователь может нажать кнопку **"ОТМЕНА"** (вместо "УДАЛИТЬ" на wireframe в контексте *добавления*), чтобы закрыть форму без сохранения.
*   **Для Просмотра/Редактирования/Удаления Источника:**
    1.  В списке источников для каждого элемента присутствуют кнопки/иконки "Редактировать" и "Удалить".
    2.  При нажатии **"Редактировать"**: Открывается форма (похожая на форму добавления, но предзаполненная данными) для изменения параметров источника. После сохранения изменений список обновляется.
    3.  При нажатии **"Удалить"**: Появляется диалог подтверждения. После подтверждения источник удаляется из списка через вызов API.

**3. Примерный UI (Концепция на основе Wireframes)**

*   **Основная Область:**

    *   Кнопка "ДОБАВИТЬ ИСТОЧНИК" (+ иконка).
    *   **Динамическая Область Добавления (появляется при клике на "ДОБАВИТЬ"):**
        *   Кнопки выбора типа: "ТЕЛЕГРАММ" | "САЙТЫ" | "API".
        *   **Динамическая Форма:**
            *   Для "САЙТЫ": Поле "URL Сайта", Поле "Название (опционально)".
            *   Для "ТЕЛЕГРАММ": Поле "Имя канала (@username или ссылка)", Поле "Название (опционально)".

**4. Архитектура FSD и Компоненты**

*   **Страница (`pages/manage-sources/ManageSourcesPage.tsx`):**
    *   Отвечает за рендеринг `ManageSourcesFeature`.
    *   При монтировании инициирует загрузку списка источников пользователя (через хук из фичи).

*   **Фича (`features/manageSources/ManageSourcesFeature.tsx`):**
    *   Основной контейнер логики управления источниками.
    *   **Состояние:** `sources` (массив источников), `isLoading`, `error`, `isAddFormVisible`, `selectedSourceType`, `formData` (для формы добавления/редактирования), `editingSource` (ID источника для редактирования, или null).
    *   **Хуки:** Использует `useSources` (или селекторы Redux) для получения/обновления списка источников.
    *   **Обработчики:**
        *   `handleAddSourceClick()`: Показывает форму добавления.
        *   `handleCancelAdd()`: Скрывает форму добавления.
        *   `handleSourceTypeSelect()`: Обновляет `selectedSourceType`, отображает нужную форму.
        *   `handleFormChange()`: Обновляет `formData`.
        *   `handleSaveSource()`: Валидирует `formData`, вызывает API (`addSource` или `updateSource`), обновляет состояние Redux/Context, скрывает форму.
        *   `handleEditClick(sourceId)`: Загружает данные источника, предзаполняет `formData`, показывает форму в режиме редактирования.
        *   `handleDeleteClick(sourceId)`: Показывает диалог подтверждения, вызывает API (`deleteSource`), обновляет состояние.
    *   **Рендеринг:** Кнопка добавления, динамическая форма добавления/редактирования (`AddEditSourceForm`), список источников (`SourcesList`).

*   **UI Компоненты Фичи (`features/manageSources/ui/`):**
    *   `AddSourceButton.tsx`: Кнопка "ДОБАВИТЬ ИСТОЧНИК".
    *   `SourcesList.tsx`: Отображает список источников, используя `SourceCardWidget`. Передает обработчики `onEdit`, `onDelete`.
    *   `AddEditSourceForm.tsx`: Контейнер для динамической формы. Содержит селектор типа и рендерит `WebsiteForm`, `TelegramForm`, `ApiForm`. Содержит кнопки "Сохранить", "Отмена".
    *   `WebsiteForm.tsx`, `TelegramForm.tsx`, `ApiForm.tsx`: Презентационные компоненты форм для конкретных типов. Получают данные и обработчики через props.

*   **Сущность (`entities/source/`):**
    *   `model/types.ts`: Интерфейс `ISource` (`id`, `userId`, `name`, `type`, `url`, `identifier` и т.д.).
    *   `api/sourceApi.ts`: Функции для взаимодействия с API (`fetchSources`, `addSource`, `updateSource`, `deleteSource`). Внутри используют API-клиент из `shared`.
    *   `model/slice.ts` (или `context.ts`): Redux slice (`sourcesSlice`) или React Context (`SourcesContext`) для хранения состояния списка источников, статусов загрузки. Содержит редьюсеры/действия для обновления состояния.
    *   `hooks/useSources.ts`: Хук для удобного доступа к данным и действиям из slice/context.

*   **Виджет (`widgets/sourceCard/SourceCardWidget.tsx`):**
    *   Компонент для отображения одного источника в списке. Принимает объект `source` как prop. Отображает название, тип, кнопки действий.

*   **Общие Компоненты (`shared/ui/`):**
    *   `Input.tsx`, `Button.tsx`, `Select.tsx` (или кастомные кнопки для выбора типа), `Modal.tsx` (для подтверждения удаления), `Spinner.tsx`, `ErrorMessage.tsx`.

**5. API Дизайн: REST API для Управления Источниками**

**Почему REST?** Операции CRUD (Create, Read, Update, Delete) для источников являются стандартными действиями "запрос-ответ", для которых REST подходит идеально. WebSocket здесь не нужен. **Все эндпоинты требуют аутентификации (JWT).**

*   **`GET /api/sources`**
    *   **Назначение:** Получить список всех источников, принадлежащих текущему авторизованному пользователю.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **Логика Backend:**
        1.  Проверить JWT, извлечь `userId`.
        2.  Найти в MongoDB (коллекция `Sources`) все документы с данным `userId`.
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        [
          { "id": "...", "userId": "...", "name": "Источник 1", "type": "website", "url": "..." },
          { "id": "...", "userId": "...", "name": "Источник 2", "type": "telegram", "identifier": "..." }
        ]
        ```
    *   **Response Body (JSON - Ошибка, 401 Unauthorized):** `{"error": "Unauthorized"}`

*   **`POST /api/sources`**
    *   **Назначение:** Создать новый источник для текущего пользователя.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **Request Body (JSON):**
        ```json
        // Пример для сайта
        {
          "name": "Название сайта (опц.)",
          "type": "website",
          "url": "https://example.com/news"
        }
        // Пример для Telegram
        {
          "name": "Название канала (опц.)",
          "type": "telegram",
          "identifier": "telegram_channel_name" // или https://t.me/channel_name
        }
        ```
    *   **Логика Backend:**
        1.  Проверить JWT, извлечь `userId`.
        2.  Валидировать входные данные (тип, URL/идентификатор).
        3.  Создать новый документ в коллекции `Sources` с указанием `userId`.
    *   **Response Body (JSON - Успех, 201 Created):**
        ```json
        { "id": "new_source_id", "userId": "...", "name": "...", "type": "...", ... } // Возвращаем созданный объект
        ```
    *   **Response Body (JSON - Ошибка, 400 Bad Request / 401 Unauthorized):** `{"error": "Invalid data"}` или `{"error": "Unauthorized"}`

*   **`PUT /api/sources/:sourceId`**
    *   **Назначение:** Обновить существующий источник.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **URL Parameters:** `:sourceId` - ID источника для обновления.
    *   **Request Body (JSON):** Поля для обновления (например, `name`, `url`).
        ```json
        {
          "name": "Новое название"
        }
        ```
    *   **Логика Backend:**
        1.  Проверить JWT, извлечь `userId`.
        2.  Найти источник по `:sourceId`.
        3.  **Проверить, что `source.userId` совпадает с `userId` из токена** (пользователь может редактировать только свои источники).
        4.  Валидировать данные для обновления.
        5.  Обновить документ в коллекции `Sources`.
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        { "id": "sourceId", "userId": "...", "name": "Новое название", ... } // Возвращаем обновленный объект
        ```
    *   **Response Body (JSON - Ошибка, 400/401/403 Forbidden/404 Not Found):** `{"error": "..."}`

*   **`DELETE /api/sources/:sourceId`**
    *   **Назначение:** Удалить существующий источник.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **URL Parameters:** `:sourceId` - ID источника для удаления.
    *   **Логика Backend:**
        1.  Проверить JWT, извлечь `userId`.
        2.  Найти источник по `:sourceId`.
        3.  **Проверить, что `source.userId` совпадает с `userId` из токена**.
        4.  Удалить документ из коллекции `Sources`.
    *   **Response Body (Успех, 204 No Content или 200 OK с сообщением):**
        ```json
        // Пример 200 OK
        { "message": "Source deleted successfully" }
        ```
    *   **Response Body (JSON - Ошибка, 401/403/404):** `{"error": "..."}`

**6. Взаимодействие с Другими Компонентами/Модулями**

*   `ManageSourcesFeature` использует API-функции из `entities/source/api` для CRUD операций.
*   Результаты CRUD операций обновляют состояние в `sourcesSlice` (Redux) или `SourcesContext`.
*   Другие страницы/фичи (например, `TextPage` для выбора источника, `Analysis Modules` для получения данных из источников) могут **читать список источников** из Redux/Context (`useSources()` хук).

**7. Безопасность**

*   **Авторизация:** Все API эндпоинты должны быть защищены (проверка JWT).
*   **Авторизация (Проверка прав):** Для операций `PUT` и `DELETE` необходимо строго проверять, что пользователь является владельцем изменяемого/удаляемого источника (сравнение `userId` из токена и `userId` в документе источника).
*   **Валидация входных данных:** На Backend необходимо тщательно валидировать все данные, приходящие от клиента (тип, формат URL, длина названия и т.д.).
