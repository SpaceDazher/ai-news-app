## Документация: Дашборд Классификации (`ClassificationDashboardPage`) и Страница Содержимого Папки (`FolderContentPage`)

**Файл:** `docs/pages/classification-dashboard.md` (или секция в `docs/pages-documentation.md`)

**1. Назначение Страниц**

*   **`ClassificationDashboardPage` (`/dashboard` или `/folders`)**:
    *   Основная страница для визуализации **тематических папок (категорий)**, созданных пользователем.
    *   Предоставляет **обзор** папок, показывает, какие источники в них входят, и отображает индикаторы **новой активности** (количество новых постов).
    *   Служит **точкой входа** для просмотра агрегированного контента по конкретной теме (папке).
    *   Позволяет **создавать** новые тематические папки.
*   **`FolderContentPage` (`/folders/:folderId`)**:
    *   Отображает **агрегированный и проанализированный контент** из **всех источников**, входящих в **выбранную тематическую папку**.
    *   Представляет новости в виде **единой ленты, отсортированной по дате**.
    *   Реализует **дедупликацию** (показывает похожие посты один раз с указанием всех источников).
    *   Отображает **сокращенный текст (резюме/тезисы)** для быстрого ознакомления.
    *   Предоставляет **инструменты фильтрации** контента внутри папки.

**2. Пользовательский Поток (User Flow)**

*   **На `ClassificationDashboardPage`:**
    1.  Пользователь видит карточки или колонки, представляющие его тематические папки.
    2.  На каждой карточке папки отображается ее название, список входящих источников (или их количество) и **количество новых/непрочитанных постов** по каждому источнику (или общее по папке).
    3.  Пользователь нажимает кнопку **"ДОБАВИТЬ"** (внизу страницы), чтобы создать новую папку (открывается модальное окно или отдельная форма для ввода названия папки и выбора источников для включения).
    4.  Пользователь нажимает кнопку **"ОТКРЫТЬ"** на карточке интересующей папки.
    5.  Происходит переход на `FolderContentPage` для выбранной папки (например, `/folders/politics`).
*   **На `FolderContentPage`:**
    1.  Пользователь видит ленту постов, агрегированных из всех источников выбранной папки, **отсортированную по дате** (сверху новые).
    2.  Каждый элемент ленты представляет собой **уникальный пост** (дедуплицированный).
    3.  Для каждого поста отображается:
        *   Дата (или группа постов под датой).
        *   Заголовок (возможно, с указанием основного источника).
        *   **Сокращенный текст/резюме**.
        *   **"ВЫВОД"** (например, оценка тональности или важности).
        *   **Ссылки внутри поста**.
        *   **"ССЫЛКИ НА САМ ПОСТ"** (список всех источников, где найден этот пост).
    4.  Пользователь может использовать **фильтры** (вверху страницы или в боковой панели) для уточнения ленты:
        *   Фильтр по дате (выбрать период).
        *   Фильтр по источнику (выбрать конкретные источники внутри папки).
        *   Фильтр по тональности (показать только позитивные/негативные/нейтральные).
    5.  Лента динамически обновляется при применении фильтров.

**3. Примерный UI (Концепция на основе Wireframes)**

*   **`ClassificationDashboardPage`:**
    *   Заголовок "Мои Темы" или "Дашборд Классификации".
    *   Сетка или колонки с виджетами папок (`FolderCardWidget`).
    *   Каждая карточка: Название папки, список источников (или иконки), число новых постов рядом с каждым источником (или общее число), кнопка "ОТКРЫТЬ".
    *   Кнопка "ДОБАВИТЬ ПАПКУ" (+ иконка) внизу или вверху.
*   **`FolderContentPage`:**
    *   Заголовок, включающий название папки (например, "Тема: Политика").
    *   **Область Фильтров:** Выпадающие списки или кнопки для фильтрации по дате, источнику, тональности.

**4. Архитектура FSD и Компоненты**

*   **Страница (`pages/dashboard/ClassificationDashboardPage.tsx`):**
    *   Рендерит `DisplayFoldersFeature`.
    *   Загружает список папок пользователя при монтировании.

*   **Страница (`pages/folders/[folderId]/FolderContentPage.tsx`):**
    *   Использует динамический роутинг Next.js для получения `folderId` из URL.
    *   Рендерит `FolderContentFeature`, передавая ему `folderId`.
    *   Загружает данные для выбранной папки.

*   **Фича (`features/manageFolders/` - часть для отображения):**
    *   `DisplayFoldersFeature.tsx`: Отображает список папок. Использует `useFolders` для получения данных. Рендерит `FolderCardWidget` для каждой папки. Включает кнопку "Добавить папку", которая может открывать модальное окно (`AddFolderModal`) для создания новой папки.
    *   `AddFolderModal.tsx` (или `AddFolderForm.tsx`): Форма для создания новой папки (название, выбор источников).

*   **Фича (`features/folderContent/FolderContentFeature.tsx`):**
    *   Основной контейнер логики для `FolderContentPage`.
    *   **Состояние:** `folderDetails` (информация о папке), `aggregatedPosts` (дедуплицированный список постов), `filters` (объект с текущими фильтрами: dateRange, selectedSources, selectedSentiment), `isLoading`, `error`.
    *   **Хуки:** `useParams` (или аналог Next.js) для получения `folderId`, `useFolderContent(folderId, filters)` (кастомный хук) для получения агрегированных постов с учетом фильтров.
    *   **Обработчики:** `handleFilterChange(newFilters)`: Обновляет состояние `filters`, что инициирует перезапрос данных через `useFolderContent`.
    *   **Рендеринг:** Компоненты фильтров (`FiltersPanel`), список постов (`AggregatedPostsList`).

*   **UI Компоненты Фич:**
    *   `features/manageFolders/ui/FolderCardWidget.tsx`: Карточка папки на дашборде.
    *   `features/folderContent/ui/FiltersPanel.tsx`: Панель с компонентами фильтров (дата, источник, тональность).
    *   `features/folderContent/ui/AggregatedPostsList.tsx`: Отображает список `AggregatedPostWidget`.
    *   `features/folderContent/ui/AggregatedPostWidget.tsx`: Отображает один дедуплицированный пост со всей информацией (заголовок, резюме, вывод, ссылки).

*   **Сущности:**
    *   `FolderEntity` (`entities/folder/`):
        *   `model/types.ts`: Интерфейс `IFolder` (`id`, `userId`, `name`, `sourceIds` (массив ID источников)).
        *   `api/folderApi.ts`: CRUD функции (`fetchFolders`, `createFolder`, `updateFolder`, `deleteFolder`).
        *   `model/slice.ts`: Redux slice (`foldersSlice`) для хранения состояния папок.
        *   `hooks/useFolders.ts`: Хук для доступа к папкам.
    *   `AnalysisResultEntity` (`entities/analysisResult/`):
        *   `api/analysisResultApi.ts`: **Новая функция** `fetchAggregatedPosts(folderId, filters)` - ключевая функция, которая будет запрашивать данные у Backend API для `FolderContentPage`.
        *   Модель для хранения и отображения агрегированных, дедуплицированных постов.

*   **Общие Компоненты (`shared/ui/`):**
    *   `Card.tsx`, `List.tsx`, `Button.tsx`, `Input.tsx`, `Select.tsx`, `DatePicker.tsx`, `Spinner.tsx`, `ErrorMessage.tsx`, `Tag.tsx` (для отображения источников).

**5. API Дизайн: REST API для Папок и Агрегированных Постов**

*   **`GET /api/folders`**
    *   **Назначение:** Получить список папок пользователя (включая ID и названия источников в папке, и, опционально, количество новых постов).
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **Логика Backend:** Найти папки пользователя, возможно, сделать доп. запросы для подсчета новых постов (может быть сложным для MVP, можно начать без счетчиков).
    *   **Response Body (JSON):**
        ```json
        [
          {
            "id": "folder1", "userId": "...", "name": "Политика",
            "sources": [ { "id": "src1", "name": "Источник А" }, { "id": "src2", "name": "Источник Б" } ],
            "newPostsCount": 25 // Опционально для MVP
          }, ...
        ]
        ```

*   **`POST /api/folders`**
    *   **Назначение:** Создать новую папку.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **Request Body (JSON):** `{ "name": "Новая папка", "sourceIds": ["src1", "src3"] }`
    *   **Логика Backend:** Валидация, проверка принадлежности источников пользователю, создание папки.
    *   **Response Body (JSON):** `{ "id": "new_folder_id", ... }` (созданная папка).

*   **`PUT /api/folders/:folderId`**
    *   **Назначение:** Обновить папку (имя, список источников).
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **URL Parameters:** `:folderId`.
    *   **Request Body (JSON):** `{ "name": "Новое имя", "sourceIds": ["src1", "src4"] }`
    *   **Логика Backend:** Валидация, проверка прав, обновление.
    *   **Response Body (JSON):** `{ "id": "folderId", ... }` (обновленная папка).

*   **`DELETE /api/folders/:folderId`**
    *   **Назначение:** Удалить папку.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **URL Parameters:** `:folderId`.
    *   **Логика Backend:** Проверка прав, удаление.
    *   **Response Body:** 204 No Content или 200 OK.

*   **`GET /api/folders/:folderId/posts`  <- Ключевой эндпоинт**
    *   **Назначение:** Получить агрегированные, дедуплицированные и отфильтрованные посты для конкретной папки.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **URL Parameters:** `:folderId`.
    *   **Query Parameters (для фильтров):**
        *   `startDate`, `endDate` (формат ISO, например, `2023-10-27T00:00:00Z`).
        *   `sourceIds` (опционально, строка ID через запятую, например, `src1,src4`).
        *   `sentiment` (опционально, `positive`, `negative`, `neutral`).
        *   `page`, `limit` (для пагинации).
    *   **Логика Backend (Сложная):**
        1.  Проверить JWT, извлечь `userId`.
        2.  Найти папку по `:folderId`, проверить принадлежность пользователю. Получить список `sourceIds` из папки.
        3.  Определить `sourceIds` для запроса (либо все из папки, либо только указанные в фильтре).
        4.  Сформировать запрос к MongoDB (коллекция `AnalysisResults`) для получения постов:
            *   Фильтр по `userId`.
            *   Фильтр по `sourceId` (используя `$in` для массива ID).
            *   Фильтр по `publicationDate` (используя `$gte`, `$lte` для диапазона).
            *   Фильтр по `sentiment` (если указан).
        5.  **Дедупликация:** Самая сложная часть. Стратегии:
            *   **Простая (MVP):** Не делать дедупликацию, просто отсортировать по дате.
            *   **Хеширование:** Группировать посты с одинаковым хешем `cleanedText` (быстро, но не ловит похожие, но не идентичные).
            *   **Семантическая близость (Продвинутая):** Вычислить векторные представления (embeddings) для `cleanedText` или `summary` (используя LangChain/Sentence Transformers), кластеризовать близкие посты и выбрать один "главный" из кластера. Требует доп. инфраструктуры и вычислений. **Рекомендуется для будущих итераций.**
        6.  **Форматирование ответа:** Для каждого уникального поста (или кластера) вернуть:
            *   Данные основного поста (заголовок, резюме, тональность, важность).
            *   Список ссылок на все исходные посты (`originalSources`: `[{sourceId, sourceName, postUrl}, ...]`).
            *   Ссылки внутри поста.
        7.  Применить пагинацию.
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        {
          "aggregatedPosts": [
            {
              "displayId": "unique_post_cluster_1", // Уникальный ID для UI
              "mainTitle": "Заголовок",
              "summary": "Краткое резюме...",
              "sentiment": "negative",
              "importanceScore": 8.5,
              "internalLinks": ["http://..."],
              "publicationDate": "...", // Дата самого раннего поста в группе
              "originalSources": [
                { "sourceId": "src1", "sourceName": "Ист. А", "postUrl": "http://..." },
                { "sourceId": "src2", "sourceName": "Ист. Б", "postUrl": "http://..." }
              ]
            }, ...
          ],
          "totalPages": 5,
          "currentPage": 1
        }
        ```
    *   **Response Body (JSON - Ошибка):** `{"error": "..."}`

**6. Взаимодействие с Другими Компонентами/Модулями**

*   `ClassificationDashboardPage` использует `useFolders` для отображения списка папок.
*   Клик на "ОТКРЫТЬ" инициирует навигацию на `FolderContentPage` с передачей `folderId`.
*   `FolderContentPage` использует `fetchAggregatedPosts` для получения данных, которые затем отображаются через `FolderContentFeature` и виджеты.
*   Фильтры на `FolderContentPage` изменяют параметры запроса к `fetchAggregatedPosts`.

**7. Безопасность**

*   **Авторизация:** Все API эндпоинты защищены JWT.
*   **Авторизация (Проверка прав):** Строгая проверка принадлежности папок и источников пользователю на всех этапах (CRUD для папок, получение постов).
*   **Валидация:** Валидация входных данных на всех API эндпоинтах.

**8. Fit в MVP**

*   **Дашборд Папок:** Реализуем отображение папок и кнопку добавления (без сложного UI редактирования источников внутри папки). Счетчики новых постов - **опционально для MVP**.
*   **Страница Содержимого Папки:**
    *   Реализуем получение постов из всех источников папки, **отсортированных по дате**.
    *   Отображаем **сохраненное резюме** и результаты анализа (тональность, важность).
    *   **Дедупликацию для MVP можно не реализовывать** или сделать по простому хешу. Полноценная семантическая дедупликация – задача для будущих итераций.
    *   Реализуем **базовые фильтры** (по дате). Фильтры по источнику и тональности – **опционально для MVP**.

Эта итерация описывает одну из самых сложных, но и самых интересных частей твоего приложения. Фокусируйся на MVP, реализуя основной поток отображения папок и агрегированных постов, а сложные вещи вроде семантической дедупликации и продвинутых фильтров оставляй на потом.
