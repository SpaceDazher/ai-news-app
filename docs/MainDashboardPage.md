## Документация: Основной Аналитический Дашборд (`MainDashboardPage`)

**Файл:** `docs/pages/main-dashboard.md` (или секция в `docs/pages-documentation.md`)

**1. Назначение Страницы**

Основной Аналитический Дашборд (`MainDashboardPage`, возможно, главная страница после входа, `/dashboard`) предназначен для предоставления пользователю **комплексного обзора аналитических данных**, полученных из обработки новостного контента по всем его источникам (или по выбранным папкам/фильтрам). Цель — быстро показать ключевые метрики, тренды, важные новости и общую картину информационного поля на основе ИИ-анализа.

**2. Пользовательский Поток (User Flow)**

*   Пользователь входит в систему и попадает на эту страницу (или переходит на нее через навигацию).
*   Дашборд **загружает и отображает агрегированные данные** за определенный период времени (по умолчанию, например, "Сегодня" или "Последние 24 часа").
*   Пользователь видит различные виджеты с ключевыми показателями, графиками и списками.
*   Пользователь может использовать **фильтр временного диапазона** (например, "Сегодня", "Последние 7 дней", "Этот месяц", выбрать диапазон дат) для обновления всех виджетов на дашборде.
*   (Опционально для MVP) Пользователь может выбрать **фильтр по тематической папке**, чтобы видеть дашборд только для новостей из этой папки.
*   При наведении на элементы графиков могут появляться всплывающие подсказки с деталями.
*   Клик на определенные элементы (например, на новость в списке) может перенаправлять пользователя на страницу с деталями (`FolderContentPage` или страницу конкретного поста).

**3. Примерный UI и Компоновка (Предложение)**

Предлагается модульный дашборд с несколькими ключевыми секциями:

*   **Верхняя Панель (KPIs / Ключевые Метрики):**
    *   Карточки с большими цифрами для быстрого обзора.
    *   Примеры метрик:
        *   "Всего Проанализировано Постов (за период)"
        *   "Средняя Тональность (за период)" (например, числовой скор или иконка)
        *   "Самая Активная Тема (за период)" (название категории)
        *   "Новых Постов Сегодня"
*   **Основная Левая Область (Динамика и Контент):**
    *   **Виджет "Последние Важные Новости":**
        *   Список из 5-10 последних постов с высокой оценкой важности (> N).
        *   Для каждого поста: Заголовок, Источник(и), Резюме (кратко), Оценка Важности, Тональность (иконка/цвет), Категория (тег).
        *   Кнопка "Показать больше" или пагинация.
    *   **Виджет "Тренд Тональности":**
        *   Линейный график, показывающий изменение средней тональности новостей во времени (по дням или часам) за выбранный период.
*   **Правая Боковая Панель (Статистика и Списки):**
    *   **Виджет "Распределение по Категориям":**
        *   Столбчатая или круговая диаграмма, показывающая процентное соотношение новостей по основным категориям за период.
    *   **Виджет "Распределение Тональности":**
        *   Круговая диаграмма (Pie/Doughnut) или столбчатая, показывающая долю позитивных, негативных и нейтральных новостей за период.
    *   **Виджет "Топ Сущностей (NER)":**
        *   Список наиболее часто встречающихся именованных сущностей (Люди, Организации) за период. Может быть в виде облака тегов или простого списка.
    *   **(Опционально для MVP) Виджет "Обнаруженные Паттерны/Аномалии":**
        *   Краткий список или уведомления о выявленных трендах или аномалиях из Модуля 7.
*   **Фильтры (вверху страницы):**
    *   Выбор Периода Дат (Date Range Picker).
    *   (Опционально) Выпадающий список для выбора Тематической Папки.

**4. Архитектура FSD и Компоненты**

*   **Страница (`pages/dashboard/MainDashboardPage.tsx`):**
    *   Рендерит `MainDashboardFeature`.
    *   Управляет базовым состоянием страницы (например, выбранный диапазон дат, папка).
    *   При изменении фильтров инициирует загрузку данных.

*   **Фича (`features/mainDashboard/MainDashboardFeature.tsx`):**
    *   Основной контейнер логики дашборда.
    *   **Состояние:** `dashboardData` (объект с данными для всех виджетов), `isLoading`, `error`, `selectedDateRange`, `selectedFolderId`.
    *   **Хуки:** `useDashboardData(selectedDateRange, selectedFolderId)` (кастомный хук) для получения всех необходимых агрегированных данных с бэкенда одним запросом (или несколькими).
    *   **Обработчики:** `handleDateRangeChange`, `handleFolderChange`.
    *   **Рендеринг:** Компоненты фильтров, сетка или компоновка виджетов (`KpiCards`, `ImportantNewsWidget`, `SentimentTrendWidget`, `CategoryDistributionWidget`, `SentimentDistributionWidget`, `TopEntitiesWidget`).

*   **UI Компоненты Фичи (`features/mainDashboard/ui/`):**
    *   `KpiCard.tsx`: Виджет для отображения одного KPI.
    *   `ImportantNewsWidget.tsx`: Отображает список важных новостей. Использует `NewsCardWidget`.
    *   `SentimentTrendWidget.tsx`: Отображает линейный график тренда тональности. Использует `shared/ui/LineChart`.
    *   `CategoryDistributionWidget.tsx`: Отображает график распределения категорий. Использует `shared/ui/BarChart` или `PieChart`.
    *   `SentimentDistributionWidget.tsx`: Отображает график распределения тональности. Использует `shared/ui/PieChart` или `BarChart`.
    *   `TopEntitiesWidget.tsx`: Отображает список или облако тегов сущностей.
    *   `NewsCardWidget.tsx`: Карточка для отображения одной новости в списке важных.

*   **Сущности:**
    *   `DashboardEntity` (`entities/dashboard/`):
        *   `model/types.ts`: Интерфейс `IDashboardData` (сложный объект, содержащий все данные для дашборда: kpis, importantNews, sentimentTrend, categoryDistribution и т.д.).
        *   `api/dashboardApi.ts`: **Новая функция** `fetchDashboardData(dateRange, folderId)` - ключевая функция API для получения всех данных дашборда.
        *   `model/slice.ts`: Redux slice (`dashboardSlice`) для хранения состояния дашборда.
        *   `hooks/useDashboardData.ts`: Хук для загрузки и доступа к данным дашборда.
    *   `FolderEntity` (`entities/folder/`): Используется для получения списка папок для фильтра.
    *   `AnalysisResultEntity` (`entities/analysisResult/`): Используется косвенно через API дашборда, которое агрегирует данные из этой коллекции.

*   **Общие Компоненты (`shared/ui/`):**
    *   `Card.tsx`, `LineChart.tsx`, `BarChart.tsx`, `PieChart.tsx` (обертки над Chart.js/Recharts), `DatePicker.tsx`, `Select.tsx`, `Spinner.tsx`, `ErrorMessage.tsx`, `Tag.tsx` (для категорий), `List.tsx`.

**5. API Дизайн: REST API для Данных Дашборда**

*   **`GET /api/dashboard`**
    *   **Назначение:** Получить **все агрегированные данные**, необходимые для отображения на основном дашборде за указанный период и/или для папки.
    *   **Request Headers:** `Authorization: Bearer <JWT>`.
    *   **Query Parameters:**
        *   `startDate`, `endDate` (обязательно, формат ISO).
        *   `folderId` (опционально): ID папки для фильтрации. Если не указан, данные по всем источникам пользователя.
    *   **Логика Backend (Сложная Агрегация):**
        1.  Проверить JWT, извлечь `userId`.
        2.  Определить `sourceIds` для запроса (все источники пользователя или источники из указанной `folderId`).
        3.  Выполнить **агрегационные запросы** к MongoDB (коллекция `AnalysisResults`):
            *   Подсчет общего количества постов за период.
            *   Расчет средней тональности за период.
            *   Определение самой частой категории (агрегация с группировкой).
            *   Подсчет новых постов за сегодня.
            *   Получение N последних постов с `importanceScore > threshold`, отсортированных по дате или важности.
            *   Агрегация данных для тренда тональности (группировка по дням/часам, расчет среднего `sentimentScore`).
            *   Агрегация данных для распределения по категориям (группировка по `category`, подсчет количества).
            *   Агрегация данных для распределения по тональности (группировка по `sentiment`, подсчет количества).
            *   Агрегация для топ-N сущностей (развернуть массив `entities`, сгруппировать по `entity.name`, подсчитать частоту, отсортировать).
        4.  Сформировать единый JSON ответ со всеми агрегированными данными. Использовать MongoDB Aggregation Pipeline для эффективности.
    *   **Response Body (JSON - Успех, 200 OK):**
        ```json
        {
          "kpis": {
            "totalPosts": 150,
            "averageSentiment": 0.1, // или "neutral"
            "topCategory": "Экономика",
            "newToday": 25
          },
          "importantNews": [
            { "id": "...", "title": "...", "summary": "...", "importanceScore": 9, "sentiment": "positive", "category": "Политика", "sources": ["..."] }, ...
          ],
          "sentimentTrend": [ // Данные для графика
            { "date": "2023-10-26", "score": 0.2 }, { "date": "2023-10-27", "score": 0.1 }, ...
          ],
          "categoryDistribution": [ // Данные для графика
            { "category": "Экономика", "count": 60 }, { "category": "Политика", "count": 40 }, ...
          ],
          "sentimentDistribution": { // Данные для графика
            "positive": 50, "negative": 30, "neutral": 70
          },
          "topEntities": [
            { "entity": "Имя Фамилия", "count": 15 }, { "entity": "Компания X", "count": 12 }, ...
          ]
          // "patterns": [...] // Опционально
        }
        ```
    *   **Response Body (JSON - Ошибка):** `{"error": "..."}`

**6. Взаимодействие с Другими Компонентами/Модулями**

*   Дашборд агрегирует данные, полученные в результате работы **всех модулей анализа**.
*   Он использует данные о **папках** (`FolderEntity`) для фильтрации.
*   Клик на новость может перенаправлять на **`FolderContentPage`** или другую страницу с деталями.

**7. Безопасность**

*   **Авторизация:** API эндпоинт `/api/dashboard` требует валидный JWT.
*   **Авторизация (Проверка прав):** Backend должен гарантировать, что агрегируются данные **только для `userId`** из токена. Если указан `folderId`, проверить принадлежность папки пользователю.

**8. Fit в MVP**

*   Реализовать базовый дашборд с основными компонентами:
    *   **KPIs:** Хотя бы "Всего постов" и "Новых сегодня".
    *   **Список новостей:** Последние N постов (без фильтра по важности), отображая название, категорию, тональность.
    *   **Графики:** Распределение по категориям (Bar) и распределение тональности (Pie).
    *   **Фильтр:** Только по дате (сегодня/неделя/месяц).
*   **Отложить на Будущее:**
    *   Сложные KPI (средняя тональность, топ тема).
    *   Фильтр по важности в списке новостей.
    *   Тренд тональности (Line chart).
    *   Топ сущностей.
    *   Паттерны/аномалии.
    *   Фильтр по папкам.
    *   Сложные агрегации на backend. Начать с более простых запросов к БД.
